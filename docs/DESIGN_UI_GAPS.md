# 모바일 UI와 기존 기능의 차이

참고 디자인의 큰 흐름을 현재 계산 엔진과 연결하면서 확인한 차이입니다. 계산 로직은 변경하지 않았습니다.

## 현재 UI에 연결한 부분

- 목표 → 레시피 → 시유 → 점검 → 소성 → 결과의 6단계 흐름
- 광택도·투명도·산화물 선택과 색상 슬라이더
- 레시피 후보 생성·선택, 비중·담금 시간·두께 계산
- 위험 판정, 적재·냉각·소성 시뮬레이션, 결과 기록
- 가정값과 검증값의 출처 표시를 접을 수 있는 정보 영역으로 유지

## 참고 디자인과 아직 맞지 않는 부분

- 참고 디자인의 로그인은 아이디 방식과 카카오·네이버·Google 버튼을 사용하지만, 현재 앱은 Supabase 이메일 로그인만 지원합니다.
- 참고 디자인의 기록 목록은 사진·소성 곡선·메모 중심이지만, 현재 서버 기록은 계산 스냅샷 JSON과 제목·공개 여부 중심입니다.
- 참고 디자인의 목표 색상은 HSL 값을 직접 다루지만, 현재 엔진은 산화물 문헌 참고색과 보정 슬라이더를 사용합니다. 색은 계산 목적함수에는 들어가지 않습니다.
- 참고 디자인의 레시피 후보 수는 최대 8개지만, 현재 엔진은 최대 12개를 허용합니다.
- 참고 디자인의 시유 화면은 단일 비중 범위와 무게 입력으로 단순화되어 있지만, 현재 엔진은 시간 경과, 담금 시간 역산, 기물 형상, 발수 면적을 별도 입력받습니다.
- 참고 디자인의 위험 화면은 세 가지 고정 항목을 보여주지만, 현재 엔진은 계산 가능 여부에 따라 판정 항목과 되돌림 선택지가 달라집니다.
- 참고 디자인의 소성 화면은 고정된 냉각 도면을 보여주지만, 현재 엔진은 냉각 구간을 사용자가 추가·삭제할 수 있고 미정 계수 E를 입력해야 시뮬레이션할 수 있습니다.
- 참고 디자인의 결과 화면은 색상·광택·치수의 좋음/보통/나쁨 평가를 사용하지만, 현재 엔진은 실제 광택도·투명도·등급·실패 이유와 보정 타일을 입력합니다.
- 참고 디자인의 공유·이미지 저장·카카오톡 공유 기능은 현재 백엔드에 대응 기능이 없습니다.
