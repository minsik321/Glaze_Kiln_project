# AICE MVP 사용자 흐름과 저해상도 와이어프레임

기준 문서: `AICE_REBUILD_TODO.md` Phase 1, `AICE_DIRECTION_PLAN.md` 1–3절·9절  
현재 앱 비교: `목표 → 레시피 → 시유 → 점검 → 소성 → 결과`의 숫자 입력 중심
6단계를 아래 9개 선택 중심 화면으로 교체한다.

## 1. 제품 범위와 사용자

MVP의 대표 사용자는 **유약과 가마의 수치 모델을 알지 못해도 시각적 안내를
따라 한 번의 가상 실험을 완료하려는 비전문가**다. 사용자는 카드와 그림을
선택하고, AICE는 선택의 이유·가정·다음 행동을 짧은 문장으로 설명한다.

이 흐름은 연구·교육용 데모다. 유약 결과를 보장하지 않으며 실제 센서에
연결하거나 실제 가마를 제어하지 않는다. 숫자 직접 입력, 원시 측정값, 수식,
계수, 상세 출처는 샘플 실행의 필수 조건이 아니다.

### 흐름 원칙

- 고정 흐름은 `사례 탐색 → 추천 → 도포 추정 → 시각화 → 곡선 보상 → 가상 소성
  → 결과 관찰 → 학습 → 공유/변환`이다.
- 기본층에는 선택 카드, 그림, 상태 문장, 짧은 근거와 한 개의 주요 행동만 둔다.
- 원시값, 단위, 수식, 계수, 모델·데이터 버전, 문헌의 정확한 위치는
  `상세 보기`에서 확인한다.
- 추천 또는 판단이 나오는 곳에는 `왜`, `가정`, `다음 행동`을 같은 순서로 둔다.
- 근거가 없거나 부족한 상태는 안전·정상으로 낮추지 않고 `판정 불가`로 표시한다.
- 모든 값은 `observed`, `patent_example`, `patent_range`, `literature`,
  `inferred`, `synthetic` 중 하나의 출처 유형을 가진다. 기본층에는 사람이 읽는
  배지, 상세층에는 원래 `source_type`과 출처·조건·단위변환·신뢰도를 표시한다.
- 사진이 없으면 색상·질감 플레이스홀더를 사용한다. 합성 시각물은 실제 결과
  사진처럼 보이게 하지 않고 `합성`을 이미지 위에 표시한다.

## 2. 공통 화면 구조와 안전 문구

모든 화면은 모바일 1열을 기준으로 다음 골격을 공유한다. 태블릿과 데스크톱은
선택 영역과 설명/시각화 영역을 나란히 놓을 수 있지만 읽는 순서는 바꾸지 않는다.

```text
┌──────────────────────────────────┐
│ AICE  [데모 · 가상 소성]   3/9 │  ← 고정 헤더
│ 지난 단계 요약          [도움말] │
├──────────────────────────────────┤
│ 화면 제목                         │
│ 지금 할 일을 설명하는 한 문장     │
│                                  │
│ [선택 카드·그림·그래프]            │  ← 기본층
│ [현재 상태 문장]                   │
│ 왜: …                             │
│ 가정: … / 판정 불가: …            │
│ 다음 행동: …                      │
│ [상세 보기 ▾]                     │  ← 상세층 진입
├──────────────────────────────────┤
│ [뒤로]             [주요 행동]    │  ← 하단 고정 행동
└──────────────────────────────────┘
```

### 고정 문구

- 헤더 배지: **`데모 · 가상 소성`**
- 배지의 접근 가능한 전체 설명: **`연구용 시뮬레이션입니다. 실제 가마와 연결되어
  있지 않습니다.`**
- 첫 진입 안내: **`AICE의 추천과 이미지는 제한된 사례·규칙·합성 데이터에 근거한
  실험 안내입니다. 실제 유약 결과나 안전을 보장하지 않습니다.`**
- 가상 소성 시작 전: **`이 실행은 화면 안의 가상 가마만 작동합니다. 실제 가마,
  히터 또는 센서에는 명령을 보내지 않습니다.`**
- 결과 화면: **`아래 결과는 합성 시뮬레이션 결과이며 실제 소성 결과가 아닙니다.`**
- 데이터가 부족한 판단: **`판정 불가 — 근거가 부족해 안전 또는 정상으로 판단할
  수 없습니다.`**

실제 제어를 암시하는 `가마 시작`, `점화`, `제어기에 전송`, `자동 운전`, `안전함`
같은 표현은 쓰지 않는다. 주요 행동은 `가상 소성 시작`, `시뮬레이션에 적용`,
`샘플 결과 보기`처럼 대상과 범위를 드러낸다.

## 3. 9개 화면 와이어프레임과 정보 우선순위

### 화면 1 — 홈 / 지난 실행

목적: 새 샘플 실행을 시작하거나 저장된 실행을 맥락과 함께 다시 연다.

```text
┌ AICE ──────── [데모 · 가상 소성] ┐
│ 유약 실험을 시각적으로 따라가요   │
│ [그림: 목표→기물→가상 가마→결과] │
│ [샘플 실행 시작]                  │
│                                  │
│ 지난 실행                         │
│ ┌ 청회색 · 반광 / 컵 ──────────┐ │
│ │ 가상 소성 완료 · 합성 결과    │ │
│ │ [이어 보기]                   │ │
│ └──────────────────────────────┘ │
│ [연구용 시뮬레이션 안내]          │
└──────────────────────────────────┘
```

기본층 우선순위: ① 샘플 실행 시작 ② 흐름 그림 ③ 지난 실행의 목표·기물·상태
④ 데모 안내. 빈 상태에서는 지난 실행 대신 `아직 저장된 실행이 없어요`를 보인다.

상세층: 실행 시각, `AiceRun` 버전, 사용한 모델 버전, 출처 유형 요약, 공개/개인
범위. 범용 JSON은 사용자에게 직접 노출하지 않는다.

상태 문장: `숫자를 입력하지 않고 준비된 샘플로 가상 실험을 시작할 수 있어요.`  
가정: `샘플 실행의 선택과 결과는 흐름 확인용 합성 데이터예요.`  
다음 행동: `샘플 실행 시작`을 눌러 원하는 결과를 고른다.

### 화면 2 — 원하는 결과 선택

목적: 광택, 투명도, 색상, 질감을 사진/스와치 카드로 선택한다.

```text
┌ 2/9 원하는 결과 ─ [데모] ────────┐
│ 어떤 느낌을 원하나요?             │
│ 색상  [청회 ●] [백색 ○] [갈색 ●] │
│ 광택  [무광] [반광 ✓] [유광]     │
│ 투명  [불투명 ✓] [반투명] [투명] │
│ 질감  [매끈 ✓] [결정] [거친]     │
│                                  │
│ 선택 상태: 청회색·반광·불투명     │
│ 가정: 색은 유사 사례를 찾는 단서  │
│       이며 결과 미리보기가 아님   │
│ [상세 보기 ▾]                     │
│ [뒤로]              [후보 보기]   │
└──────────────────────────────────┘
```

기본층 우선순위: ① 큰 스와치/사진 카드 ② 선택 상태 문장 ③ 가정 문구 ④ 후보 보기.
고급 수치 조절은 기본층에 두지 않는다.

상세층: 선택 축의 내부 값, 허용 범위, 색상 표현 방식, 검색에 사용되는 필드,
선택하지 않은 특성의 처리, 접근성용 텍스트 레이블.

왜: `선택한 카드는 다음 화면에서 유사 사례를 찾는 비교 기준이 돼요.`  
가정: `화면 색은 목표를 표현하는 참고값이며 소성 후 색을 보장하지 않아요.`  
다음 행동: `후보 보기`로 최대 3개의 유사 레시피를 비교한다.

### 화면 3 — 사진이 있는 레시피 후보 비교

목적: 최대 3개의 후보를 사진과 핵심 차이로 비교하고 하나를 선택한다.

```text
┌ 3/9 레시피 후보 ─ [데모] ─────────┐
│ 목표와 가까운 사례 3개예요         │
│ ┌사진 A────────┐ ┌사진 B────────┐ │
│ │ 자체 관측     │ │ 합성          │ │
│ │ 청회 반광     │ │ 청회 무광     │ │
│ │ 데이터 8건    │ │ 데이터 없음   │ │
│ │ 위험: 판정불가│ │ 위험: 판정불가│ │
│ │ [선택 ✓]      │ │ [선택]        │ │
│ └──────────────┘ └──────────────┘ │
│ 왜: 목표의 색·광택과 가장 가까움   │
│ 가정: 다른 소지/가마 결과는 다름   │
│ 다음 행동: 후보를 고르고 기물 선택 │
│ [배합·출처 상세 보기 ▾]            │
│ [뒤로]          [이 후보로 계속]   │
└───────────────────────────────────┘
```

기본층 우선순위: ① 사진 또는 명시적 플레이스홀더 ② 목표와의 유사 이유
③ 실제/합성 및 출처 배지 ④ 소성 범위·데이터 수·불확실성·위험 요약 ⑤ 선택.

상세층: 배합 백분율, UMF/화학 상세, 원 조건과 소성조건, 공보번호·문헌 위치,
단위변환, 랭킹 규칙, 모델 버전, 전체 가정과 신뢰도. `patent_example`,
`patent_range`, `literature`, `inferred`, `synthetic`, `observed`를 원문 그대로
확인할 수 있어야 한다.

왜: `선택한 후보는 목표의 색·광택·투명도 조건과 비교 후보 중 가장 가까워요.`  
가정: `사진은 유사 사례이며 같은 결과를 보장하는 미리보기가 아니에요.`  
다음 행동: `이 후보로 계속`을 눌러 기물과 소지를 고른다.

### 화면 4 — 기물 모양 및 소지 선택

목적: 치수 입력 대신 대표 형상과 소지를 카드로 고른다.

```text
┌ 4/9 기물과 소지 ─ [데모] ─────────┐
│ 무엇에 유약을 바를까요?            │
│ [사발] [접시] [컵/머그 ✓]          │
│ [원통 화병] [병] [타일/평판] [기타]│
│ 대표 크기: [작음] [보통 ✓] [큼]   │
│ 시유 면:   [안+밖 ✓] [밖] [안]    │
│ 소지: [백자토 ✓] [석기토] [기타]  │
│ [그림: 선택한 컵 실루엣]           │
│ 가정: 대표 형상으로 면적을 추정함  │
│ [상세 보기 ▾]                      │
│ [뒤로]            [도포 샘플 적용] │
└───────────────────────────────────┘
```

기본층 우선순위: ① 형상 실루엣 카드 ② 대표 크기 ③ 안/밖 시유 ④ 소지 카드
⑤ 선택한 조합 그림. `기타`는 간단한 설명과 사진/실루엣 선택만 받고 정밀 치수나
사용자 메시 업로드를 요구하지 않는다.

상세층: 프리셋의 대표 면적과 범위, 면적 산출 방식, 초벌 조건, 프리셋 버전,
출처 유형과 신뢰도. 대표값은 `observed`가 아니며 근거에 맞춰 `literature`,
`inferred` 또는 `synthetic`으로 표시한다.

왜: `이 프리셋은 선택한 기물·크기·시유 면과 가장 가까운 대표 형상이에요.`  
가정: `면적과 위치는 선택한 대표 형상에 근거한 추정이며 실제 기물 치수가
아니에요.`  
다음 행동: `도포 샘플 적용`으로 준비된 시유 기록을 불러온다.

### 화면 5 — 도포 기록과 유약 단면 확인

목적: 준비된 도포 샘플을 적용하고, 평균 추정과 위치별 가상 분포를 구분해 본다.

```text
┌ 5/9 도포와 단면 ─ [데모] ─────────┐
│ 도포 샘플                         │
│ [표준 담금 ✓] [얇은 도포] [두꺼움]│
│                                  │
│      ╭──── 컵 종단면 ────╮       │
│      │ //// 목표 근처 ////│       │
│      ╰─ 굽: 두꺼울 수 있음╯       │
│ [패턴 범례: 얇음/목표/두꺼움/?]    │
│ 두께 표현은 이해를 위해 과장됨     │
│ 상태: 평균은 가정 기반 추정        │
│ 위치별 분포: 형상 기반 가상 분포   │
│ 왜: 굽에 유약이 모일 수 있음       │
│ 가정: 직접 구간 측정은 없음        │
│ 다음 행동: 적재와 센서를 선택      │
│ [측정·수식·불확실성 상세 보기 ▾]   │
│ [뒤로]                 [계속]      │
└───────────────────────────────────┘
```

기본층 우선순위: ① 패턴과 레이블을 함께 쓴 기물 종단면 ② 평균 상태 문장
③ 위치별 근거 수준 ④ 굽·모서리·안쪽 바닥 위험 콜아웃 ⑤ 다음 행동. 색만으로
상태를 구분하지 않는다.

상세층: 비중·전후 무게·담금시간·면적·건조밀도 등 원시값과 단위, 계산식,
보정계수, 적용 조건, 오차범위, 출처 유형. 미정 계수는 값으로 채우지 않고
`미정`과 동정 방법을 보인다.

왜: `선택한 샘플과 형상에서는 굽 주변이 상대적으로 두꺼울 수 있어요.`  
가정: `전체 무게를 이용한 평균 추정이며 위치별 모양은 설명용 가상 분포예요.`  
다음 행동: `계속`을 눌러 가마 안의 위치와 센서 구성을 고른다.

### 화면 6 — 가마 적재 및 센서 배치

목적: 가마 종단면에서 적재와 센서 프리셋을 고르고 관측 한계를 이해한다.

```text
┌ 6/9 적재와 센서 ─ [데모] ─────────┐
│ 적재: [가볍게 ✓] [보통] [가득]    │
│ 센서: [기본 1개] [상·중·하 3개 ✓] │
│                                  │
│ ┌──────── 가마 단면 ───────────┐ │
│ │ ● 상단 센서  [컵]             │ │
│ │ ● 중단 센서  [컵] [컵]       │ │
│ │ ● 하단 센서  [컵]             │ │
│ │ ~ 열선  | 단열벽 | 배기       │ │
│ └──────────────────────────────┘ │
│ 상태: 세 층의 차이를 비교 가능    │
│ 가정: 온도장은 설명용 근사         │
│ 다음 행동: 보정 곡선 후보 확인     │
│ [센서 사각지대·적재 상세 보기 ▾]   │
│ [뒤로]             [곡선 후보 보기]│
└───────────────────────────────────┘
```

기본층 우선순위: ① 선반·열선·문/뚜껑·배기·단열벽이 구분된 가마 종단면
② 적재 프리셋 ③ 센서 프리셋 ④ 각 센서의 측정 대상과 사각지대 ⑤ 관측 가능성
상태 문장.

상세층: 가마 프로필, 열용량·열손실·출력의 근거, 센서 위치 좌표, 센서 편향과
고장 시나리오, 적재량과 불확실성, 물리 모델과 시각 효과의 데이터 분리.

왜: `상·중·하 센서는 층별 차이를 비교하지만 기물 내부 온도를 직접 재지 않아요.`  
가정: `열 분포와 대류 표현은 정량 CFD가 아닌 설명용 근사예요.`  
다음 행동: `곡선 후보 보기`에서 기준 계획과 수정 계획을 비교한다.

### 화면 7 — 보정 소성곡선과 PID 계획 확인

목적: 계획이 언제, 어느 방향으로, 왜 바뀌었는지 이해하고 가상 실행 후보를
승인한다.

```text
┌ 7/9 곡선과 제어 계획 ─ [데모] ────┐
│ [그래프]                            │
│ ─ 기준 계획   ━ 두께 반영 수정 계획│
│ ↑ 이 구간: 두꺼운 굽 위험을 고려   │
│ 제어 방식                           │
│ [빠른 반응] [균형 ✓] [안정 우선]   │
│ 상태: 최고온도 유지 / 시간 늘어남  │
│ 왜: 도포 추정과 적재 편차를 반영   │
│ 가정: 규칙 기반 합성 후보           │
│ 다음 행동: 승인한 후보만 가상 실행 │
│ [게인·제약·원시 곡선 상세 보기 ▾]  │
│ [뒤로]        [시뮬레이션에 적용]   │
└────────────────────────────────────┘
```

기본층 우선순위: ① 기준 계획과 수정 계획 그래프 ② 변경 구간 직접 주석
③ `빠른 반응/균형/안정 우선` 프리셋 ④ 최고온도·유지·냉각·시간/에너지 차이의
자연어 요약 ⑤ 왜/가정/다음 행동. 그래프는 색뿐 아니라 선 종류와 레이블을 쓴다.

상세층: P/I/D 게인, 포화, anti-windup, 샘플링 주기, 안전 제약, 목적함수,
원시 곡선, 후보 버전과 선택 이유. 활성화 에너지 등 미정 계수는 근거 없는
기본값으로 채우지 않는다.

왜: `도포와 적재의 추정 편차를 줄이는 방향으로 제한된 구간만 바뀌었어요.`  
가정: `수정 계획은 제한된 규칙과 합성 시나리오의 후보이며 최적임을 보장하지
않아요.`  
다음 행동: `시뮬레이션에 적용`으로 선택한 후보만 가상 제어기에 전달한다.

### 화면 8 — 가상 소성 진행

목적: 같은 시간축에서 목표, 센서, 기물 추정, 히터 출력과 경보를 관찰한다.

```text
┌ 8/9 가상 소성 ─ [데모 · 실행 중] ─┐
│ 이 실행은 실제 장치를 작동하지 않음│
│ [가마 열지도 + 느린 설명용 흐름선] │
│ [▶ 재생] [Ⅱ 일시정지] [구간 이동] │
│ ─ 계획  ━ 센서  ┄ 기물 추정        │
│ 진행: 유지 구간 · 가상 68%          │
│ 상태: 중단 센서 추종 중              │
│ 경고: 하단 편차 관찰                 │
│ [센서·출력·오차 로그 상세 보기 ▾]   │
│ [가상 실행 중단]     [샘플 결과 보기]│
└────────────────────────────────────┘
```

기본층 우선순위: ① 실제 장치 비연결 문구 ② 시간 재생과 현재 구간 ③ 가마
열지도 ④ 계획·센서·기물 추정의 동기화 그래프 ⑤ 히터 출력·경보 상태. 대류는
느린 흐름선으로 표현하고 `설명용 근사` 레이블을 붙인다.

상세층: 전체 시계열, 열일, 추종오차, 출력 제한, 센서 이상·과열·추종 실패 로그,
난수 시드, 시뮬레이터와 제어기 버전, 모든 값의 `synthetic` 출처.

왜: `현재 경고는 합성 센서와 기물 추정 사이의 편차에서 발생했어요.`  
가정: `센서·기물 온도·열 흐름은 모두 합성 시뮬레이션 값이에요.`  
다음 행동: 실행 완료 뒤 `샘플 결과 보기`에서 목표와 비교한다.

### 화면 9 — 결과 평가와 다음 제안

목적: 합성 결과를 목표와 비교하고 다음 실행에 반영될 제안을 확인한다.

```text
┌ 9/9 결과와 다음 제안 ─ [데모] ─────┐
│ 합성 시뮬레이션 결과 · 실제 아님    │
│ [결과 플레이스홀더: SYNTHETIC]      │
│ 목표 대비                           │
│ 색 [가까움] 광택 [조금 낮음]        │
│ 질감 [선택] 투명도 [선택] 결함 [?]  │
│ 상태: 결함은 판정 불가              │
│ 왜: 실제 사진·관측값이 없기 때문    │
│ 가정: 선택 평가는 샘플 응답         │
│ 다음 제안: 유지 구간 후보를 비교    │
│ [학습·출처·공유 상세 보기 ▾]        │
│ [처음으로]           [실행 저장]    │
└────────────────────────────────────┘
```

기본층 우선순위: ① 합성 결과 고정 표시 ② 목표 대비 색·광택·질감·투명도와
결함 평가 ③ `판정 불가` ④ 다음 실행 제안 ⑤ 저장. 사용자가 직접 관측하지 않은
결과를 `observed`로 저장하지 않는다.

상세층: 표준 촬영 조건 안내, 결과 라벨, 공통/개인 잔차 분리, 다음 제안에 반영된
필드, 데이터·모델 버전, 동의와 공개 범위, 공유/변환 제한. 개인 보정은 공통
모델에 자동 합치지 않으며, 공유는 명시적 동의가 있을 때만 가능하다.

왜: `실제 결과 사진과 관측값이 없으므로 결함과 품질은 판정할 수 없어요.`  
가정: `현재 평가는 흐름 확인용 샘플 응답이고 다음 제안도 합성 후보예요.`  
다음 행동: 실행을 개인 기록으로 저장하거나 처음으로 돌아간다.

## 4. 기본층과 상세층의 전역 정보 우선순위

| 순위 | 기본층 | 상세 보기 |
|---|---|---|
| 1 | 지금 선택하거나 관찰할 카드·그림 | 원시 입력값과 단위 |
| 2 | 현재 상태를 설명하는 한 문장 | 계산식, 계수와 적용 조건 |
| 3 | `왜`·`가정`·`다음 행동` | 출처 원문 위치와 단위변환 |
| 4 | 실제/추정/합성 등 출처 배지 | 전체 `source_type`, 신뢰도와 불확실성 |
| 5 | 한 개의 주요 행동 | 모델·데이터·스키마 버전과 원시 로그 |

예외적으로 안전 경고, `판정 불가`, 실제 장치 비연결, 합성 이미지 표시는 접지
않고 항상 기본층에 둔다. 상세 보기를 열어야만 데이터 성격을 알 수 있는 설계는
허용하지 않는다.

## 5. 클릭형 샘플 실행 인수 조건

Phase 2 이후 구현될 클릭형 프로토타입은 아래 조건을 모두 만족할 때 Phase 1의
흐름 계약을 충족한 것으로 본다.

### 숫자 입력 없는 완주 시나리오

1. 사용자가 홈에서 `샘플 실행 시작`을 누른다.
2. 스와치 카드로 `청회색·반광·불투명·매끈` 목표를 선택한다.
3. 사진/플레이스홀더가 있는 후보 중 하나를 선택한다.
4. `컵/머그·보통·안+밖·백자토` 카드를 선택한다.
5. `표준 담금` 샘플을 선택하고 단면과 근거 수준을 확인한다.
6. `가볍게 적재·상중하 3개 센서` 프리셋을 선택한다.
7. 수정 계획과 `균형` 제어 프리셋을 선택해 시뮬레이션에 적용한다.
8. 가상 소성을 재생하거나 `샘플 결과 보기`로 완료 상태까지 진행한다.
9. 합성 결과를 확인하고 샘플 평가를 선택한 뒤 실행을 저장한다.

### 객관적 통과 기준

- 위 경로에서 숫자 입력 필드는 한 번도 포커스하거나 수정하지 않아도 된다.
- 새 실행부터 저장 완료까지 마우스/터치와 키보드만으로 각각 완주할 수 있다.
- 각 화면은 선택 전·선택 후 상태와 한 개의 명확한 주요 행동을 제공한다.
- 화면 3, 5, 6, 7, 8, 9에 `왜`, `가정`, `다음 행동` 문구가 보인다.
- 9개 화면 모두 고정 헤더에서 `데모 · 가상 소성`을 확인할 수 있다.
- 가상 소성 직전에는 실제 가마·히터·센서에 명령을 보내지 않는다는 문구가
  확인되며, 실행 버튼의 이름은 `가상 소성 시작` 또는 동등하게 명확한 표현이다.
- 추천 후보와 결과 시각물은 실제/특허/문헌/추론/합성 성격을 기본층 배지로
  구분하고, 상세 보기에서 여섯 `source_type` 중 정확한 값을 확인할 수 있다.
- 근거가 부족한 위험·결함·품질은 `판정 불가`로 보이며 정상 또는 안전으로
  표시되지 않는다.
- 평균 두께 추정과 위치별 가상 분포, 센서 온도와 기물 추정온도, 기준 계획과
  수정 계획을 문구와 선/패턴으로 각각 구분한다.
- `상세 보기`를 열지 않아도 선택과 완주가 가능하고, 열면 원시값·단위·출처·
  불확실성·버전을 잃지 않고 확인할 수 있다.
- 마지막 저장 기록은 목표, 후보, 기물/소지, 도포 샘플, 적재/센서, 선택 곡선,
  합성 실행, 샘플 평가와 각 단계의 출처·가정·버전을 하나의 `AiceRun`으로
  연결할 수 있어야 한다.
- 실제 품질 보장, 실제 가마 자동 운전, 실제 센서 연결 또는 검증되지 않은
  최적성을 암시하는 문구와 행동이 없다.

## 6. 현재 앱에서의 전환 경계

현재 앱의 계산 코어와 `판정 불가` 원칙은 유지 대상이다. 다만 현재 UI의 후보
개수, 탐색 간격, 배치량, 비중, 무게, 담금시간, 초벌온도, 냉각구간, 최고온도,
PID 관련 값 등의 직접 입력은 샘플 흐름의 기본층에서 제거한다. 준비된 선택
프리셋이 동일한 원시값 묶음을 만들고, 계산 코어에는 그 원시값을 전달한다.

프런트엔드는 계산을 재구현하지 않는다. 실제 계산 결과가 필요한 시점에는 기존
Python 코어 또는 이후 결정될 계산 API의 타입 있는 결과를 표시한다. 근거가
없는 프리셋 값과 미정 계수를 조용한 기본값으로 채우지 않으며, 샘플용 값은
`synthetic` 또는 적절한 출처 유형과 가정을 명시한다.
