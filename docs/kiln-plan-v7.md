## 00 · 주장하지 않는 것

문서 앞에 둔다. 뒤에서 지키기 위해서다.

- **실제 품질이 개선된다고 주장하지 않는다.** 실물 소성이 없다.
- **조성으로 결과를 예측한다고 주장하지 않는다.** 실험 데이터가 없다.
  (착색 산화물 참고 색상표는 예외로 범위를 좁혀 둔다 — 4-4절. 이 레시피가
  실제로 어떤 색으로 나올지의 예측이 아니라, 문헌에 보고된 대표 색상의
  열람·보간이다. 근거는 4-3절 Stull 참조와 같다: 계산해서 보여주되 판정으로
  쓰지 않는다.)
- **탐색이 목표에 수렴한다고 주장하지 않는다.** 자기 생성 데이터로는 증명되지 않는다.
- 계수(k₁, k₂, ρ_dry, E, α, β)의 값을 주장하지 않는다. **동정 절차만 주장한다.**

주장하는 것은 하나다. **계측 → 판단 → 제어 → 기록이 하나의 사이클로 동작하고, 그 사이클이 재현에 필요한 값을 자동으로 남긴다.**

## 01 · 문제 정의

### 레시피가 정하는 것은 전체의 일부다

```
레시피가 정하는 것      원료 비율

레시피 밖에 있는 것     물을 얼마나 넣어 개었는가      → 비중
                        몇 초 담갔는가                 → 두께
                        어느 부위가 얼마나 두꺼운가    → 분포
                        어떤 열이력을 받았는가         → 실제 소성
                        얼마나 천천히 식혔는가         → 냉각
                        가마 어디에 놓였는가           → 위치 편차
```

문제는 정보의 부족이 아니라 **정보의 소실**이다.

### 대표 사례 — 석회 매트

석회·저실리카 매트는 냉각 중 결정 석출로 무광이 된다. **조성이 같고 최고온도 같아도 급냉하면 광택, 서냉하면 매트로 나온다.**

레시피는 이 차이를 담지 못한다. 조성 기반 예측은 원리적으로 이 차이를 맞힐 수 없다. 이 한 사례가 04절부터 09절까지의 근거다.

*(v5는 "콘을 바꾸면 Stull 경계가 이동한다"를 근거로 썼다. 문헌 사례가 하나뿐이고 이동량을 함수로 만들 수 없으므로 보조 근거로 강등한다.)*

### 과제

> 유약 두께, 배치 비중, 적재 열용량, 실제 열이력, 냉각 프로파일을 각각 **정량 관측**하고, 이를 결합해 소성을 **결정·제어**하며, 그 전 과정을 **자동으로 기록**하여 재현 가능한 단위로 만든다. 회차가 쌓이면 그 기록이 **다음 실험의 탐색 범위**를 좁힌다.

기록은 목적이 아니라 제어의 부산물이다.

## 02 · 기존 도구와의 차이

### Glazy.org

레시피 DB이자 화학 계산기. 다루는 범위는 **배합 단계까지**다. 공개 데이터는 CC BY-NC-SA 4.0이며, 수치는 활용하고 이미지·설명은 링크로 참조한다. 비영리 조건이므로 사업화 시 별도 검토가 필요하다.

### GlazyBench

조성으로부터 소성 후 색·투명도·표면질감을 예측하는 과제를 정의한 연구용 데이터셋. 공개된 성능은 최다 클래스 추정과 비슷하거나 낮았다.

**원인은 두 층에 걸쳐 있다.**

```
입력 결손    22차원 중 소성 관련은 콘 범위 2개와 분위기 2개가 전부
             같은 "콘 6 환원"에 급냉과 서냉이 같은 샘플로 들어감
             → 같은 입력에 다른 정답

라벨 노이즈  사용자 사진에서 자동 추출한 라벨의 노이즈가
             달성 가능한 성능의 상한을 제한 (저자들이 인정)
```

본 시스템은 전자를 **제어와 기록**으로, 후자를 **표준 촬영과 라벨 정의**로 다룬다.

*(v5는 원인을 입력 결손 하나로 단정했다. 저자가 인정한 것은 라벨 쪽이었으므로 병렬로 고친다. 두 원인은 처방이 다르고, 본 시스템은 양쪽을 다룬다.)*

### 상용 가마 컨트롤러

콘 보정(열일 환산)은 일부 상용 컨트롤러가 이미 제공한다. 차이를 구성요소 수준으로 적는다.

| | 상용 컨트롤러 | 본 시스템 |
|---|---|---|
| 열일 보정 | 일부 모델이 제공 | 제공 |
| 보정의 입력 | 온도 이력만 | **유약 두께 · 배치 비중 · 적재 열용량** |
| 냉각 | 프로그램된 램프 | **결정 성장 구간의 목표 냉각률 추종** |
| 결정 대상 | 사용자가 넣은 스케줄 실행 | **스케줄 자체를 결정** |
| 기록 | 온도 로그 | **조성·두께·적재·결과까지 한 단위** |

## 03 · 시스템 구조 — 두 개의 루프

```
[바깥 루프 — 회차 사이, 주 단위]        조성 탐색

 ①  목표 지정         광택도 × 투명도 격자에서 한 칸        (04절)
 ②  탐색 범위 제시     사전분포 + 축적 데이터                (05절)
 ③  후보 생성          N개, 한 소성 시편 수에 맞춤
 ④  사용자 선택

                        ↓

[안쪽 루프 — 회차 내, 시간 단위]        계측 · 판단 · 제어

 ⑤  배치 제조          비중 실측 · 교반 후 경과 기록          (06절)
 ⑥  시유               담금시간 역산 → 저울 2회 → 두께 분포   (07절)
 ⑦  위험 판정          5종 · 되돌림 비용 선택지               (08절)
 ⑧  적재               점유율 산출 · 총량 이상 감지           (09절)
 ⑨  소성               승온·유지: 열일 추종 / 냉각: 냉각률 추종 (09절)
 ⑩  자동 기록          스케줄·실측 곡선·두께·비중이 부산물로 남음

                        ↓

[되먹임]

 ⑪  결과 입력          3축 라벨 (10절)
 ⑫  계수 보정          k₁ · ρ_dry (저비용, 매 회차)
 ⑬  탐색 갱신          목표 거리 → 유망 영역 갱신
 ⑭  다음 후보          범위 축소 · 격자 세분

                        └──────→ ①
```

**두 루프의 관계가 이 시스템의 논거다.**

바깥 루프는 관측 노이즈에 민감하다. 두께가 회차마다 ±0.3mm 흔들리면 조성 ±2%p 차이는 그 안에 묻힌다. **안쪽 루프가 통제되지 않으면 바깥 루프의 신호가 잡음이 된다.** GlazyBench가 부딪힌 벽과 같은 벽이며, 탐색 루프를 도입했기 때문에 계측·제어가 더 필요해진다.

| 루프 | 갱신 대상 | 신호 | 주기 |
|---|---|---|---|
| 안쪽 | k₁, ρ_dry, k₂, 안전 두께 범위 | 무게·캘리퍼·파단면 | 회차마다 |
| 바깥 | 유망 조성 영역 | 광택도·투명도 좌표 | 회차마다 |

## 04 · 목표 좌표계

### 4-1. 광택도 × 투명도

```
축 1  광택도   Dry — Matte — Satin — Semi-gloss — Gloss    (5단계 순서형)
축 2  투명도   불투명 — 반불투명 — 반투명 — 투명           (4단계 순서형)
```

두 축은 독립이다(불투명 광택, 투명 매트가 모두 존재). 순서형이라 거리가 정의되고, **사용자가 소성 결과를 보고 같은 척도로 고를 수 있다.**

*(Dry–Matte–Clear 삼각좌표는 폐기한다. 셋은 배타적 성분이 아니라 용융도가 올라가는 한 축 위의 순서이고, 표면은 한 상태만 가지므로 "Dry 60 / Matte 30 / Clear 10"이 정의되지 않는다. 더 결정적으로 소성 결과를 그 척도로 매기는 방법이 없다. 목표와 결과가 같은 척도 위에 있어야 ⑬이 성립한다.)*

### 4-2. 목표 공간과 조성 공간의 분리

**사용자는 "어떤 느낌을 원하는가"를 2차원에서 고르고, 내부 엔진이 3원료 또는 4원료 조합을 탐색한다.** 이것이 v6.1에서 편입한 개정안의 핵심 아이디어이며, 삼각좌표 한 점을 그대로 배합비로 해석하던 v5 방식을 대체한다.

```
[사용자 화면]                    [내부 엔진]

  투명도                          규석 · 장석 · 석회석 (+카올린)
    ↑   ┌───┬───┬───┬───┐               ↓
    │   │   │ ● │   │   │        후보 배합 생성
    │   ├───┼───┼───┼───┤               ↓
    │   │   │   │   │   │        목표 좌표와의 예상 거리 평가
    └───┴───┴───┴───┴───→ 광택도         ↓
                                  후보 N개 제시
```

### 4-3. Stull 좌표는 판정이 아니라 참조로

UMF 좌표는 계산해서 보여주되, **질감을 확정하는 근거로 쓰지 않는다.**

- 판정을 쓴다면 SiO₂:Al₂O₃ 비 1차원이 아니라 **(SiO₂, Al₂O₃) 2차원 영역**으로 한다. 비 하나로 축약하면 석회석 축이 판정에서 사라진다(05-2절 계산 참조).
- 영역 경계는 **문헌 추정 초기값**이며 화면과 문서 양쪽에 그렇게 표기한다. 부록 C 등록.
- **저실리카 매트와 미용융은 Stull 좌표상 같은 방향이라 차트만으로 갈리지 않는다.** 갈라주는 것은 콘·유지시간·냉각이다. 이것이 04절이 09절을 필요로 하는 이유다.
- 콘 슬라이더로 경계가 연속 이동하는 UI는 삭제한다. 이동량을 산출할 함수가 없다. **이산 프리셋(콘 6 / 콘 11)으로 하고 각각의 출처를 병기한다.**

### 4-4. 색은 예측하지 않는다

같은 착색제도 기저 조성·두께·냉각에 따라 결과가 달라진다. 색은 목적함수에 넣지 않고 **부수 관측**으로만 기록한다. 조건이 맞는 사례를 보여줄 때는 그 사례에 기록된 소성 정보가 무엇인지 함께 표시한다.

### 4-4-a. 착색 산화물 참고 색상표 (예외 범위)

도예 실무에서 통용되는 **6종 대표 착색 산화물** — 철(Fe₂O₃) · 동(CuO) · 크롬(Cr₂O₃) · 코발트(CoO) · 니켈(NiO) · 망간(MnO₂) — 에 한해, 문헌에 보고된 **일반적인 참고 색상**을 표로 제공한다. 사용자는

- 표에서 산화물 하나를 그대로 고르거나,
- 두 산화물의 참고 색상 사이 **사잇값**(선형 보간)을 고르거나,
- **첨가량**(건조 재료 대비 wt%, 문헌 통상범위 기준)을 조절하거나,
- 고른 색의 **채도·명도**를 조정

할 수 있다. 사잇값·첨가량·채도·명도 중 **무엇을 조절해도** 화면에는 최종
색 하나만 뜨는데, 이 시스템은 그 최종 색을 "중성 바탕색(첨가 0%) → 문헌
참고색(통상 첨가량 상한)" 직선에 **정사영**해서 첨가량을 되짚고, 그 값과
사용자가 입력한 배치 무게로 그램 수를 낸다. 채도·명도를 크게 틀어 그
직선을 벗어난 색을 만들면 "이 산화물 조합의 첨가량 조절만으로는 이 색이
그대로 나오지 않는다"는 일치도 경고가 함께 뜬다 — **정사영은 기하 근사이지
화학 역산이 아니다.**

**이것이 4-4절의 원칙을 어기지 않는 이유.** 4-3절이 Stull 좌표를 "계산해서
보여주되 판정으로 쓰지 않는" 것과 같은 자리에 둔다 — 산화물별 참고 색상은
**문헌값의 열람과 보간**이지, "이 레시피·이 소성 조건에서 실제로 이 색이
나온다"는 예측이 아니다. 그래서:

- 참고 색상은 목적함수 d(5-4절)에 들어가지 않는다. 04-1절 목표 축은 여전히
  광택도 × 투명도 2축뿐이다.
- 조성 탐색(05절)의 입력으로도 쓰이지 않는다 — 원료 5종(규석·장석·석회석·
  카올린·벤토나이트, 05-1절)에 착색 산화물이 추가되는 것이 아니다.
- 화면에 표시할 때는 **항상** "문헌 참고값 — 기저 조성·두께·소성 분위기·
  냉각에 따라 실제 결과는 달라진다"는 문구를 병기한다(부록 C·4-3절과 같은
  출처 병기 원칙). 이 문구가 빠지면 참고표가 예측으로 읽힌다.
- **통상 첨가량·산화 소성 기준값 하나만 등록한다.** 분위기나 농도에 따라
  크게 달라지는 산화물(예: 구리는 환원에서 붉게 변한다, 크롬은 극소량 +
  주석 함유 유약에서 녹색 대신 핑크가 된다)은 그 사실만 주석으로 남기고
  별도 색상값이나 농도별 표를 만들지 않는다. 조건별로 표를 늘리는 것은
  "실험 데이터 없이 값을 늘린다"는 00절 위반으로 되돌아가기 때문이다.

## 05 · 조성 탐색

### 5-1. 원료의 세 역할 분리

| 역할 | 원료 | 처리 |
|---|---|---|
| 현탁제 | 벤토나이트 소량 | **고정.** 탐색 변수 아님 |
| 알루미나 공급원 | 카올린 | **고정 배경 비율(10–15%)** 위에서 3원료 삼각 |
| 탐색 확장 | 카올린 비율 | 목표 미달 시에만 추가 차원으로 열기 |

**근거 ①** 규석·장석·석회석 세트는 알루미나 공급원이 장석 하나뿐이다.

```
도달 범위   SiO2:Al2O3 비 최소 5.97(장석 단독), Al2O3 UMF 최대 1.01
            → 비 6.0 아래 = 알루미나 매트 원리적 도달 불가

카올린 비율에 따른 이동
  카올린  0%  Al2O3 0.27  비 15.19
  카올린 10%  Al2O3 0.42  비 10.26
  카올린 20%  Al2O3 0.62  비  7.63
  카올린 30%  Al2O3 0.88  비  6.00   ← 장석 단독 수준에 겨우 도달
```

**카올린 30%는 확장 변수가 아니라 배합의 주성분이다.** 0%에서 출발하면 탐색 초기 구간 전체가 고실리카·저알루미나 영역에 갇힌다.

**근거 ②** 점토질은 슬립 현탁제 역할이 크다. 점토가 없으면 유약이 통에서 가라앉고 생소지 부착력이 떨어진다. 침강은 06절 비중 관리와 직결된다.

### 5-2. 격자 간격 — 노이즈보다 커야 한다

```
v6.1 이전 1차 탐색 후보 (±2%p 격자)
  A 규석40 장석40 석회20  →  SiO2 4.04  Al2O3 0.27
  B 규석42 장석38 석회20  →  SiO2 4.14  Al2O3 0.26
  C 규석40 장석38 석회22  →  SiO2 3.73  Al2O3 0.24
  D 규석38 장석42 석회20  →  SiO2 3.94  Al2O3 0.28
  후보 간 SiO2 UMF 최대 차이 = 0.403

석회석만 10%p씩 벌린 격자
  10% → 6.83     20% → 4.04     30% → 2.65     40% → 1.81
  → 석회석 10%p 하나가 위 전체 폭의 6~13배
```

```
1차   삼각형 전체를 10%p 격자로 (66점 중 6~10점 표집)
2차   유망 영역 주변 5%p
3차   2%p
```

**격자 간격은 관측 노이즈보다 커야 한다.** 노이즈의 지배적 성분은 조성이 아니라 시유 두께이므로, 안쪽 루프의 두께 통제가 격자 해상도의 상한을 정한다.

### 5-3. 2계층 실험 설계

**한 소성에 조성은 여러 개 시험할 수 있지만 소성 조건은 하나뿐이다.**

```
한 소성에 시편 20개 배치 가능하다고 가정

조성 2차원(3원료)     10%p 격자 = 66점    → 소성 3~4회면 전면 커버
조성 3차원(4원료)     10%p 격자 = 286점   → 소성 15회 (주1회면 4개월)
소성 조건 3변수       회차당 1점만 관측    → 20회차 = 20점
```

| 계층 | 변수 | 방법 |
|---|---|---|
| 내부 (회차 내) | 조성 | 격자 / DoE, 배치 병렬 |
| 외부 (회차 간) | 최고온·유지·냉각률 | **순차 1변수, 사전 지식 기반** |

**소성 조건에 베이지안 최적화를 쓰지 않는다.** 3차원 공간에 20점은 BO가 작동할 밀도가 아니다. BO·Active Learning·GP는 **조성 계층에 한정**해서 적용하며, 그것도 충분한 회차가 쌓인 뒤다.

```
1단계   소성 조건 고정(레퍼런스 스케줄) → 조성만 탐색
2단계   조성 확정 후 → 소성 조건 1변수씩 (냉각률 우선: 석회 매트 지배 변수)
```

### 5-4. 목적함수

```
d = w1 · |광택도_목표 − 광택도_결과| + w2 · |투명도_목표 − 투명도_결과|

  w1, w2 : 사용자가 UI에서 조정 (기본 1:1)
  부수 관측(색·흐름·핀홀·결정)은 d에 넣지 않고 필터로만 사용
```

**필터로 쓴다**는 것은 예컨대 "흐름 발생" 시편을 목표 거리와 무관하게 후보에서 제외한다는 뜻이다. 가중치를 정의할 근거가 없는 항목을 목적함수에 억지로 넣는 것보다 정직하다.

### 5-5. 사전분포 — 콜드 스타트 해법

실험 1회 = 배합 + 시유 + 건조 + 소성 + 냉각. 개인 작업실 기준 주 1회. **개인 데이터만 쓰면 첫 몇 달이 비어 있다.**

```
사전분포   문헌 + Glazy 공개 데이터의 조성-결과 분포
              ↓
개인 데이터가 사전분포를 갱신 (경험적 베이즈 구조)
              ↓
회차가 쌓일수록 개인 데이터의 가중치가 커짐
```

**사전분포는 조성 축에만 정보를 준다. 소성 축은 개인 데이터로만 채워진다.** Glazy 사례에는 소성 정보 칸이 비어 있기 때문이다. 이 비대칭 자체가 02절 진단의 재확인이다.

**축적 데이터는 목표별이 아니라 조성→결과 매핑으로 저장한다.** 목표별로 저장하면 사용자가 목표를 바꿀 때마다 리셋된다.

## 06 · 배치와 비중

### 6-1. 비중은 고정, 담금시간만 역산

두께를 결정하는 미지수는 비중과 담금시간 둘인데 목표는 하나다. 동시 역산하면 해가 무수히 많으므로 **비중을 고정하고 담금시간만 역산**한다.

```
t_dip = [ (t_목표 − t_flow) / (k₁ · 흡수율 · g(ρ)) ]²

  ρ를 상수로 고정 → 미지수 하나 → 해가 유일
  t_목표 < t_flow 인 경우의 도메인 가드 필요 (음수 제곱 방지)
```

실무적으로도 이쪽이 맞다. 이미 개어둔 유약통의 비중을 지금 바꾸는 것보다 "지금 이 통으로 몇 초 담그면 되는가"가 필요한 답이다.

### 6-2. 비중의 작용 경로 수정

**v5는 비중을 흡수층(t_abs)에만 넣었다. 물리적으로는 반대다.** 고형분이 오르면 항복응력이 급격히 올라 흘러내리는 막이 두꺼워진다. v5 본문이 "되직 → 두껍게 붙어 흘러내림 위험"이라고 서술해놓고 수식은 그 경로를 갖고 있지 않았다.

```
v5   t_flow = k2 · sinθ(z) · (h_max − z)/h_max
v7   t_flow = k2 · m(ρ) · sinθ(z) · (h_max − z)/h_max
     m(ρ) : 파라미터 1개짜리 단조증가 함수, 부록 C 등록
```

### 6-3. 측정 이벤트 — 비중은 배치가 아니라 순간에 귀속된다

비중을 재고 몇 분 뒤 담그면 이미 다르다. 점토가 적은 배합일수록 침강이 빠르다.

```
유약 레시피
 └─ 배치 (배합일 · 원료 로트)
     └─ 측정 이벤트 (측정 시각 · 교반 후 경과 시간 · 실측 비중)
```

경과 시간이 임계를 넘으면 재측정을 권고한다.

### 6-4. 경고 분기

| 상태 | 물리적 의미 | 안내 |
|---|---|---|
| 범위 초과(되직) | 고형분 과다 — 두껍게 붙고 흘러내림 위험 | 물 소량 추가 후 재측정 권장 |
| 범위 미달(묽음) | 고형분 부족 — 얇게 붙고 편차 확대 | 가라앉힌 뒤 위 맑은 물 따라내고 재측정 |
| 극단적 이탈 | 모델 적용 범위 밖 | 예측 신뢰도 낮음 명시, 진행 여부 확인 |

경고가 떠도 진행을 막지 않는다. 화면의 권장 범위 수치에는 `(문헌 추정 초기값 · 캘리브레이션 전)`을 병기한다.

## 07 · 두께 산출

### 7-1. 계산 구조

```
A    = ∫ 2πr(z) √(1 + (dr/dz)²) dz         표면적 (파푸스·굴딘)
θ(z) = arctan(dz/dr)                       벽면 경사각

t(z) = t_abs + t_flow(z)
       t_abs  = k₁ · √(담금시간) · 흡수율 · g(ρ)          위치 무관
       t_flow = k₂ · m(ρ) · sinθ(z) · (h_max − z)/h_max   경사각 의존

총량 제약   ∫ t(z) · dA(z) = W / ρ_dry
```

사용자가 하는 일은 **저울에 두 번 올리는 것**(시유 전 / 건조 후)과 형태 유형을 고르는 것뿐이다.

### 7-2. 총량 제약이 보장하는 것과 보장하지 않는 것

v5: "총량 제약 때문에 평균 두께는 k₂ 오차와 무관하게 **항상 실측과 일치**한다."

**두 가지가 틀렸다.**

1. **동어반복이다.** 평균 = 총부피/총면적이고 제약을 그렇게 걸었으니 당연히 일치한다. 모델이 맞힌 게 아니라 나눗셈이다.
2. **"실측과 일치"가 거짓이다.** 실제로 계산되는 값은 `W/(A·ρ_dry)`인데 ρ_dry가 v5에 없었다.

```
W=96g, A=0.060 m² 인 머그
  ρ_dry=1.3 → 1.23mm     1.5 → 1.07mm     1.7 → 0.94mm
  1.6으로 가정했는데 실제 1.35면 19% 과소평가
  표면적 A가 템플릿 대비 ±8%면 두께도 ∓8%
```

08절 안전 범위가 0.8–1.3mm다. **ρ_dry 하나로 안전창이 한 칸 통째로 이동한다.**

교체 서술:

> 평균 두께는 `W/(A·ρ_dry)`로 산출된다. k₂ 오차와 무관하지만 **ρ_dry와 A의 정확도에는 직접 의존한다.** 총량 제약이 보장하는 것은 "모델이 분포를 어떻게 그리든 총량은 일치한다"는 내적 정합성이지, 실측과의 일치가 아니다.

| | 정확도 의존 |
|---|---|
| 평균 두께 | **ρ_dry · A 에 의존** (k₂에는 무관) |
| 위치별 분포 | k₂ 에 의존 |
| 국소 최대 두께 | k₂ 에 의존 — **가장 불확실하며, 흘러내림 판정의 근거** |

### 7-3. 캘리브레이션 — 저울 + 캘리퍼

**저울만으로는 ρ_dry를 식별할 수 없다.** 무게 데이터에서 ρ_dry와 평균두께는 곱으로 붙어 분리되지 않는다.

```
1. 평평한 타일 3~4장을 서로 다른 담금시간으로 시유
2. 건조 후 무게 측정        → k₁ 회귀
3. 건조 후 두께 캘리퍼 측정 → ρ_dry = W/(A·t)
   * 파괴 불필요, 소성 불필요, 도구는 캘리퍼 1개
```

**특허 실시가능성 관점에서 이 절차가 명세서의 핵심이다.** 계수가 미정이어도 동정 절차가 개시되어 있으면 요건을 충족한다.

### 7-4. 압밀 계수 s

예측은 **생유약 두께**, 파단면 실측은 **소성 후 유리질층 두께**다. 소성 중 유약층은 압밀되어 얇아진다. 그대로 빼서 오차로 쓰면 계수가 반대 방향으로 수렴한다.

```
오차 = (t_예측 · s) − t_파단면실측       s = 소성후/생,  s < 1
```

**s와 k₂는 같은 신호(파단면 두께)에만 영향을 주므로 분리 동정되지 않는다.** s를 유약별 고정 상수로 두고 부록 C에 등록한다.

### 7-5. 적용 조건

| 항목 | 처리 |
|---|---|
| 시유 방법 | 담금: 분포 모델 / 부기·분무·붓칠: **총량만** |
| 굽 닦기 | 무게 측정은 굽 닦기 **직전** 고정 |
| 왁싱(발수제) | **왁스 무게는 시유 전 무게에 포함, 왁스 부위 면적은 A에서 제외.** 미처리 시 총량 앵커가 깨짐 |
| 슬립 교반·침강 | 측정 시각·교반 후 경과 기록. 임계 초과 시 재측정 권고 |
| 건조 종료 판정 | 무게 변화가 임계 이하로 안정된 시점. 잔류 수분 2%면 두께 2% 과대 |
| 재시유 후 흡수율 | 재습윤으로 흡수율 변화. **모델 적용 범위 밖**으로 표시, 신뢰도 하향 |
| 내부 시유 | 여부 입력 → 표면적 반영 |
| 초벌 온도 | 변경 시 **재캘리브레이션 트리거** (흡수로 처리하지 않음) |
| 소지 종류 | 흡수율·가스방출·열팽창이 달라짐. 기물 등록 시 필수 |
| 원료 로트 | 산지·로트 편차. 배치에 로트 필드 |

### 7-6. 시각화

| 단계 | 표시 |
|---|---|
| 전체 | 기물 실루엣, 부위별 색으로 얇음/안전/두꺼움 |
| 부위 확대 | 벽 단면 — 소지층과 유약층 2겹, 두께 수치 병기 |
| 대조 | 파단면 촬영 시 예측 단면과 나란히 |

유약층은 과장해서 그린다(실제는 소지의 수 %). **눈으로는 두껍게, 숫자로는 정확하게 병기**한다.

### 7-7. 사후 진단 — 파단면이 있을 때만

편차비 = 1 + k₂·m(ρ)/t_abs 이고 t_abs는 사용자가 입력한 비중의 함수다. **예측 편차비로 진단하면 결론은 "당신이 낮은 비중을 입력했습니다"뿐이다.** 자기 입력을 되돌려준다.

이 기능은 **파단면 실측이 있는 회차에만 활성화**한다. 실측이 없으면 표시하지 않는다.

### 8-2. 시유 방법별 가용 판정

분포 모델이 담금 전용이므로 담금이 아니면 분포 기반 판정이 작동하지 않는다.

| 시유 방법 | 가용 판정 |
|---|---|
| 담금 | 5종 전부 |
| 부기·분무·붓칠 | 평균 기반만 (미용융 · 기포 · 결정 과다) |
| | 흘러내림 · 응력 균열은 **「판정 불가」로 회색 처리** |

이 층 구조는 명세서에도 유리하다. **총량 기반 판정이 상위, 분포 기반 판정이 하위**로 나뉜다.

### 8-3. 두께만으로 갈리지 않는 분기

```
두꺼움 + 기포 위험     → 유지 연장     (열을 더)
두꺼움 + 흘러내림 위험 → 최고온 하향   (열을 덜)
```

어느 쪽이 먼저 터지는지는 유약의 용융 범위와 소지의 가스 방출 온도대가 결정하는데, **시스템이 관측하는 값이 아니다.** 숨기지 않고 3단계로 처리한다.

| 단계 | 방식 |
|---|---|
| 초기 | 두 위험을 모두 표시, 사용자가 선택 |
| 유약 등록 시 | 사용자가 유형 지정 |
| 이력 축적 후 | 그 유약의 실제 실패 유형으로 자동 분기 |

### 8-4. 대응 선택지 — 되돌림 비용 병기

| 선택지 | 되돌림 비용 | 효과 |
|---|---|---|
| **재시유** | 건조 재소요 + **흡수율 변화로 모델 적용 범위 밖** | 가장 확실하나 예측 신뢰도 하향 |
| 부분 보정 | 수 분 | 국소 위험 완화 |
| 적재 조정 | 없음 | 2차 피해 방지 |
| 스케줄 보정 | 없음 | **효과 불확실** |
| 그대로 진행 | 없음 | — |

```
┌─────────────────────────────────────┐
│  ⚠ 흘러내림 위험 — 높음             │
│  굽에서 12mm 지점 두께 1.72mm       │
│  이 유약의 안전 범위 0.8–1.3mm      │
│  (문헌 추정 초기값 · 캘리브레이션 전)│
│  ─────────────────────────────────  │
│  ● 재시유          건조 4시간 재소요 │
│     → 권장 담금시간 1.2초           │
│     → 예상 두께 1.05 ± 0.25mm       │
│     → 재습윤으로 예측 신뢰도 하향    │
│  ○ 부분 보정       5분              │
│  ○ 적재 조정       비용 없음        │
│  ○ 스케줄 보정     효과 불확실       │
│  ○ 그대로 진행                      │
└─────────────────────────────────────┘
```

*(v5는 재시유 예측에만 `✓ 안전` 확정 기호를 붙였다. 07절에서 "국소 최대 두께가 가장 불확실"이라고 못 박고 스케줄 보정에는 "효과 불확실"을 붙여놓은 것과 태도가 어긋났다.)*

## 09 · 적재와 소성 제어

### 9-1. 제어가 있어야 하는 두 이유

**① 품질** — 컨트롤러는 벽 센서 하나로 판단하지만 기물이 받은 열은 다르다.

**② 데이터** — 소성이 통제되지 않으면 결과에 "그날 그 가마가 어땠는지"가 잡음으로 섞인다. 03절의 두 루프 구조에서 바깥 루프의 신호가 무너진다.

> 제어는 품질을 위한 장치이면서 동시에 **데이터 계층을 성립시키는 전제**다.

### 9-2. 적재 — 총량 이상 감지로 한정

```
등록된 기물 목록 → 투영 면적 합 → 점유율 → F(점유율), h(점유율)
```

승온 응답 역산으로 적재량을 검증하는 것은 **분해능이 부족하다.**

```
30L 가마(내화물 45kg, 선반 6kg), 100℃/h
  기물  0kg → 1400 W       3kg → 1467 W (+4.8%)      10kg → 1622 W (+15.9%)
  10kg 등록 vs 12kg 실제 = 신호 차 2.7%

계통 불확실: 공급전압 ±5% → 전력 ±10% / 열선 노후 −5~15% / 내화물 축열 침투 지연
```

**신호가 계통 불확실보다 작다.** 기능 목표를 **총량 이상 감지(gross error detection)**로 낮추고, 임계값을 계통 불확실보다 크게 잡는다. "적재 오등록 판별"은 주장하지 않는다.

센서 이상(온도 정체·급변 등 물리적으로 불가능한 패턴)은 별개이며, 알림 후 일시 정지하고 사람이 개입할 때까지 자동 진행을 금지한다.

### 9-3. 열일

```
H(t) = ∫₀ᵗ exp( −E / (R · T_s(τ)) ) dτ

  T_s : 센서 기준 온도 (기물 온도가 아님 — 아래 참조)
  E   : 겉보기 활성화 에너지. 값 미정, 부록 C
```

**T의 정의를 센서 기준으로 못 박는다.** v5는 T가 무엇인지 쓰지 않았다. 센서 온도라면 9-1 ①이 스스로 부정한 값이고, 기물 온도라면 실물에서 관측 불가다. 시뮬레이터에서는 노드 온도가 다 있으니 돌아가지만 그건 관측 문제를 회피한 것이다.

> 본 시스템은 **센서 기준 열일 H_s**를 정의하고, 기물–센서 오프셋을 가마 프로필의 캘리브레이션 대상으로 둔다. "기물이 받은 열을 직접 제어한다"고 주장하지 않는다.

### 9-4. 구간별 제어 구조

| 구간 | 내측 루프 | 외측 루프 | 추종 대상 |
|---|---|---|---|
| 승온 | 온도 PID | **감시 모드** | 원본 스케줄 |
| 유지 | 온도 PID | **능동 모드** | 누적 열일 H_s |
| **냉각** | 온도 PID | **없음(단일 루프)** | **목표 냉각률 궤적** |

**냉각을 H로 환산하지 않는 이유:** 결정 석출은 특정 온도대의 체류 시간이 결정하는 양이고, H는 급냉과 서냉을 구분하지 못한다.

```
급냉(310℃/h) + 1220℃ 유지 49분   H = 7801
서냉(77.5℃/h) + 1220℃ 유지 15분   H = 7801   ← 동일, 질감은 정반대
```

### 9-5. 외측 루프 모드 전환

H는 거의 전부 최상단에서 쌓인다.

```
100℃/h · 1220℃ · 유지 15분 (총 12.25h)
   6h(620℃)  0.00%    8h(820℃)  0.01%
  10h(1020℃) 1.26%   11h(1120℃) 10.75%
  → H의 90%가 마지막 1.29시간에 누적
  → 3h 시점 H_목표 = 5.6e-14  ← 상대오차 분모로 사용 불가
```

```
감시 모드   누적 H < 목표의 1%
            보정 출력 0, 원본 스케줄 추종, 이상 감시만

능동 모드   누적 H ≥ 목표의 1%
            Δt_eq = (H_목표 − H_실제) / exp(−E/R·T_peak)      [초]
            → "유지 7분 부족" 형태로 화면 표시
```

*(v5의 `e_H = (H_목표 − H_실제)/H_목표`는 소성 앞 80% 구간에서 0으로 나눈다. 당업자가 그대로 구현하면 실패하므로 실시가능성 요건상 반드시 고쳐야 한다.)*

### 9-6. 냉각 제어의 물리적 범위

**전기가마는 서냉만 제어 가능하고 급냉은 제어 대상이 아니다.**

```
30L 가마, C=58 kJ/K, 1220℃ 유지전력 2.5kW로 UA 역산 (선형 근사)

자연냉각률(제어 상한)  1220℃ 155  /  1000℃ 127  /  800℃ 101  /  600℃ 75  [℃/h]

결정 성장 구간 1100→900℃ 서냉 비용
   126 ℃/h   1.6h   자연냉각, 추가전력 0
    80 ℃/h   2.5h   평균 751W    +1.9 kWh
    50 ℃/h   4.0h   평균 1234W   +4.9 kWh
    30 ℃/h   6.7h   평균 1556W   +10.4 kWh
```

*선형 UA 근사는 고온 복사 손실을 과소평가한다. 실제 자연냉각률은 이보다 빠를 수 있다. 상대 비교용으로만 쓴다.*

- 냉각 스케줄 UI에 **자연냉각률 곡선을 배경으로 표시**하고 그 아래만 선택 가능하게 한다.
- 서냉 선택 시 **추가 시간과 전력량을 병기**한다(08절 되돌림 비용과 같은 원칙).
- **573℃ 석영 전이 구간**은 별도 처리한다. 빠르게 통과하면 소지가 균열된다. 결정 성장 구간과 목적이 다르므로 냉각을 두 구간으로 나눈다.

### 9-7. 안전 설계 — 아키텍처별 분리

| | A. 스케줄 주입 (1차) | B. 직접 제어 (향후) |
|---|---|---|
| 안전 로직 | 기존 컨트롤러 | 본 시스템 + 하드웨어 컷오프 |
| 출력 비율 결정 | 기존 컨트롤러 | 본 시스템 |
| 우리가 하는 것 | 스케줄 결정 · 모니터링 · 유지 연장 요청 | 전부 |
| 전제 | **컨트롤러 통신 인터페이스 개방** | 릴레이 접근 |

**A에서 외측 루프의 실시간 보정은 제한된다.** 상용 컨트롤러 다수는 프로그램을 미리 넣고 실행하는 구조라 실행 중 램프·홀드 교체가 안 된다. 타깃 모델이 정해지기 전까지 A에서 가능한 것은 `사전 스케줄 결정 + 모니터링 + 유지 연장 요청` 수준으로 적는다.

공통 안전 장치(어느 아키텍처든): 하드웨어 상한 컷오프, 워치독, 열전대 단선 감지, 승온율 하드 리밋.

## 10 · 기록과 되먹임

### 10-1. 결과 기록 — 3축

```
축 1  목표 좌표   광택도(5단계) × 투명도(4단계)      ← 목적함수 입력
축 2  등급        의도일치 / 허용 / 실패             ← 전반적 방향 신호
축 3  실패 유형   (등급=실패일 때 다중 선택)
                  흘러내림 / 미용융 / 기포 / 균열 / 결정과다
부수  색 · 흐름 · 핀홀 · 표면 결함                    ← 필터로만 사용
```

**등급과 목표 좌표는 다른 축이다.** 3단계 등급은 만족도이지 질감이 아니므로, 그것만으로는 탐색도 Stull 경계 보정도 못 한다.

3단계 등급의 약점("허용"의 주관성)은 **개인 1인 시스템이므로 일관성만 있으면 문제되지 않는다.** 다중 사용자 확장 시에는 사용자 간 정규화가 필요하다(부록 B).

### 10-2. 계수 보정 — 신호와 비용을 함께 적는다

| 보정 대상 | 필요 신호 | 획득 비용 | 표기 |
|---|---|---|---|
| k₁ (흡수) | 무게 역산 | **매 회차, 저울만** | **실선** |
| ρ_dry | 캘리퍼 1회 | 캘리브레이션 시 1회 | **실선** |
| k₂ (경사) | 파단면 관찰 | 파괴 필요, s와 분리 불가 | 점선 |
| Stull 경계 | 표면 유형 라벨 | 라벨 축적 | 점선 |
| 안전 두께 범위 | 실제 실패 발생 지점 | 이항 사건, 수십 회차 | 점선 |
| 위험 분기 우선순위 | 실패 유형 분류 | 위보다 더 많이 | 점선 |

**"저울 두 번으로 k₁이 수렴한다"만 주장해도 충분하고, 그것만 주장하면 반박당하지 않는다.**

### 10-3. 처방 — 구현 제외, 기재 유지

개인 1대 범위이므로 발행은 스키마만, 수신 변환은 데모로 둔다. 다만 설계는 명시한다.

**v5의 대비축이 틀렸다.** E가 주어지면 `dH/dτ = exp(−E/RT)`이므로 H(t)와 T(t)는 일대일 변환이다. 정보량이 같으므로 한쪽이 가마 의존이고 다른 쪽이 독립일 수 없다. 실제 구분은 **컨트롤러 설정값 vs 달성된 열이력**이다.

| | v5 | v7 |
|---|---|---|
| 표의 축 | 온도 곡선 / 열일 곡선 | **설정 스케줄 / 달성 열이력** |
| 공유 단위 | H(t) 곡선 하나 | **H_s(승온·유지) + 냉각 온도 곡선** |
| 냉각 | H에 합산 | **분리. 온도–시간으로 그대로** |
| 변환 실패 조건 | 없음 | **B의 자연냉각률이 A보다 느리면 재현 불가** |

마지막 행이 중요하다. 처방 변환은 **비대칭**이다 — 서냉은 이식 가능하고 급냉은 아닐 수 있다.

**E 불확실이 변환에 미치는 영향:**

```
1220℃ 15분 유지와 같은 H를 내는 저온 유지시간
  E=200 kJ/mol   1200℃ 18.7분   1180℃ 23.4분   1150℃ 33.1분
  E=300 kJ/mol   1200℃ 20.8분   1180℃ 29.2분   1150℃ 49.2분
  E=400 kJ/mol   1200℃ 23.2분   1180℃ 36.4분   1150℃ 73.2분
```

온도차가 작으면 E를 몰라도 되고, 벌어질수록 오차가 그대로 나온다.

**E 동정 경로:** 콘은 같은 열일에서 휘므로, 서로 다른 승온율에서의 도달온도 쌍이 곧 E 방정식 하나가 된다. 절차만 적고 **수치는 Orton 공식 자료로 직접 대조한 뒤 채운다. 대조 전에는 문서에 쓰지 않는다.**

```
사용자 1명
 ├─ 가마 프로필 N개        (등록 실물 1대 + 검증용 가상 프로필)
```

**적용 범위 표(개인 · 공동 작업장 · 교육기관 · 소규모 제조)는 문서에 그대로 둔다.** 구현 범위 축소는 12절에서만 표시한다.

### 12-2. 검증 — 순환을 피하는 설계

**생성기와 추정 모델이 같으면 어떤 수렴도 자명하다.** v5의 "더미 20회차 수렴"이 그랬고, 탐색 루프를 넣으면 같은 순환이 더 큰 규모로 돌아온다.

```
시뮬레이터에 반드시 주입할 것
  공급전압 변동 ±5% · 열선 열화 · 열전대 노이즈와 지연
  적재 열용량 미스매치 · 벽체 축열 침투 지연
  시유 두께 회차간 변동 · 비중 측정 오차
  광택도·투명도 라벨링의 사람 오차 (±1단계)

생성기는 추정 모델과 구조적으로 다르게 (오지정)
  k₂ 위치 의존 · 인출 속도 랜덤 · 요변성 · ρ_dry 편차
```

| 검증 항목 | 방법 | 가능 |
|---|---|---|
| 제어 루프가 설계대로 동작하는가 | 목표 H_s 추종, 외란 주입 후 회복 | 가능 |
| 냉각률 추종이 자연냉각 상한을 지키는가 | 상한 초과 요청 시 거부·경고 | 가능 |
| **분포 예측이 균일 두께 가정보다 나은가** | 오지정 생성기 대비 위치별 RMSE | 가능 |
| **α·β를 얼마나 틀리면 위험 판정이 뒤집히는가** | 뒤집힘 임계 산출 | 가능 |
| **오지정 하에서 예측 오차가 줄어드는가** | "수렴"이 아니라 "RMSE X% 감소, Y% 편향 잔존" | 가능 |
| **격자 간격이 노이즈보다 작으면 오판정하는가** | 5-2절 근거의 정량화 | 가능 |
| 처방이 다른 가마 조건으로 변환되는가 | 프로필 2종에 같은 H_s | 가능 |
| **실제 품질이 개선되는가** | — | **불가** |
| **조성이 이 질감을 낸다** | — | **불가** |
| **탐색이 목표에 수렴한다** | — | **불가** |

*(v5 검증표의 "k₂ ±50% 스윕에도 평균 두께 보존"과 "α·β 부호 유지"는 삭제한다. 전자는 총량 제약을 걸고 총량을 확인하는 산수, 후자는 단조감소 함수의 단조성 확인이다.)*

### 12-3. 전문가 타당성 검토

실측이 불가능한 조건에서의 유일한 외부 검증.

```
1. 시뮬레이터로 시나리오 10건 실행
2. 시스템이 낸 판단과 선택지를 정리
3. 도예 전공자에게 제시: "이 판단이 말이 됩니까?"
4. 어긋나는 지점 → 모델 결함 / 맞는 지점 → 설계 근거
```

시나리오는 지어내지 않고 문헌과 Glazy의 실제 실패 사례를 재구성한다.

|---|---|

| 2–4주 | 계산 코어 — 두께 엔진, UMF, 목적함수·격자, 시뮬레이터(외란 포함) |
| 5–6주 | 제어기 — 구간별 루프, 모드 전환, 냉각률 추종, 자연냉각 상한 |

## 부록 D · 특허 기재 방침

*변리사가 아닌 입장에서의 기술 문서 작성 방침이며, 청구항 구성과 선행조사는 변리사 판단이다.*

구성요소를 많이 묶은 청구항은 넓어지지 않고 좁아진다. 하나만 빼고 구현하면 침해가 아니다. 그리고 모듈마다 선행 대비 위치가 다르다.

| 모듈 | 선행 대비 위치 |
|---|---|
| 두께 계측 (저울 2회 + 총량 제약 + ρ_dry 동정) | **가장 단단함** |
| 위험 판정 + 되돌림 비용 선택지 | 두께에 종속되나 구성은 독립 |
| 목표 좌표계와 조성 공간의 분리 | 신규 |
| 2계층 실험 설계 (조성 병렬 / 소성 조건 직렬) | 신규 |
| 사전분포 + 개인 데이터 갱신 | 신규 |
| 냉각률 추종 (결정 성장 구간) | 열일 제어와 분리하면 독립 가치 |
| 열일 기반 제어 | **약함** — 상용 컨트롤러에 유사 보정 존재 |
| 처방 변환 | 개념은 신규할 수 있으나 실시가능성 약함 |

**기재 포맷 — 모듈마다 고정 4항목:**

```
① 입력   무엇을 받는가 (센서 · 사용자 · 이력)
② 처리   어떤 연산·판정을 하는가 (수식과 임계 포함)
③ 출력   무엇을 내는가 (값 · 경고 · 제어 신호)
④ 차이   이 모듈 단독으로 선행 대비 무엇이 다른가
```

그 위에 **「결합 효과」 절**을 따로 둔다. "두께를 알아야 스케줄이 달라지고, 스케줄이 통제돼야 기록이 성립하며, 기록이 있어야 탐색과 계수 보정이 성립한다"는 인과를 한 절에 모은다. 통합 청구항의 근거가 여기서 나온다.

**이렇게 쓰면 변리사가 쪼갤 수도 있고 묶을 수도 있다. 통합만 서술하면 쪼갤 재료가 없다.**

**AI를 판단 주체로 쓰지 않는다.** 명세서는 "AI가 판단한다"가 아니라 어떤 입력으로 어떤 연산을 해 어떤 출력을 내는지로 써야 실시가능성이 선다. 탐색 엔진은 규칙/최적화 알고리즘으로 명시하고, LLM을 쓴다면 자연어 입출력 껍데기로 한정한다.
