# kiln.firing — 09절 적재와 소성 제어

기획서 전문: [`../../../docs/kiln-plan-v7.md`](../../../docs/kiln-plan-v7.md) 09절
(9-1 ~ 9-7절), 10-3절, 12-2절, 부록 A · C · E.
경계 계약: [`../../../docs/INTERFACES.md`](../../../docs/INTERFACES.md) `kiln.firing` 절.
폐기된 설계: [`../../../docs/DECISIONS.md`](../../../docs/DECISIONS.md).

부록 D 고정 4항목. 다루는 범위는 이 모듈(`heatwork.py` · `loading.py` ·
`cooling.py` · `simulator.py` · `controller.py`) 단독이며, 처방 발행·변환은
`kiln.exchange`, 두께·위험은 `kiln.thickness`/`kiln.risk` 문서를 본다.

9-1절이 제어를 요구하는 이유가 둘이라는 점이 이 모듈의 성격을 정한다.
**① 품질** — 컨트롤러는 벽 센서 하나로 판단하지만 기물이 받은 열은 다르다.
**② 데이터** — 소성이 통제되지 않으면 결과에 "그날 그 가마가 어땠는지"가
잡음으로 섞여 03절 바깥 루프의 신호가 무너진다. 제어는 품질을 위한 장치이면서
동시에 **데이터 계층을 성립시키는 전제**다.

## ① 입력

- **센서** — `(시각[s], 센서온도[℃])` 점열. 실물에서 관측 가능한 유일한
  온도다(9-3절). 기물 온도는 입력이 아니다.
- **설정 스케줄** — `FiringRun.schedule` 과 같은 `(시각[s], 목표온도[℃])` 점열.
  승온·유지·냉각 구간이 기울기로 구분된다.
- **가마 프로필**(`KilnProfile`) — 유효 열용량 C, 벽체 손실 계수 UA, 최대 출력,
  자연냉각률 곡선. 냉각의 **제어 상한**이 여기서 나온다(9-6절).
- **적재** — 등록된 기물 목록(`Ware.footprint_area`), 선반 면적, 빈 가마
  기준 유지전력과 관측 유지전력.
- **냉각 요청** — `CoolingSegment(from_c, to_c, rate_c_per_h, purpose)` 열.
- **활성화 에너지 E** — 부록 C **미정**. 호출부가 `assume_E(값, 사유)` 로
  가정을 세워야만 들어온다. 기본값은 없다.
- **외란**(`Disturbance`) — 공급전압 ±5%, 열선 노후 −5~15%, 열전대 잡음·지연,
  적재 오차, 축열 침투 지연. `seed` 하나로 재현된다(12-2절).

## ② 처리

### 열일 H_s — `heatwork.py` (9-3절)

```
H_s(t) = ∫₀ᵗ exp( −E / (R · T_s(τ)) ) dτ        R = 8.314462618 J/(mol·K)
```

**T는 센서 온도로 못 박는다.** 기물 온도라면 실물에서 관측 불가이고,
시뮬레이터의 노드 온도로 대신하면 관측 문제를 회피한 것이 된다(부록 E #2).
기물–센서 오프셋은 `constants.get("sensor_offset")` (미정)으로 남기고
**"기물이 받은 열을 직접 제어한다"고 주장하지 않는다.**

exp(−E/RT)는 온도에 대해 극단적으로 볼록해서 성긴 사다리꼴 적분이 크게
틀린다. 구간마다 지수 φ의 변화량이 0.02를 넘지 않도록 **자동 세분**한다 —
30분 간격으로 샘플링한 곡선과 5초 간격 곡선이 1e-4 안에서 일치한다.

### Δt_eq — `heatwork.py` (9-5절, 부록 E #3)

H는 거의 전부 최상단에서 쌓인다. 100℃/h·1220℃(20℃ 출발, 총 12.25h)에서

| 시점 | 6h(620℃) | 8h(820℃) | 10h(1020℃) | 11h(1120℃) |
|---|---|---|---|---|
| 누적 H 비율 | 0.00% | 0.01% | 1.26% | 10.75% |

**H의 90%가 마지막 1.29시간에 누적된다.** 3시간 시점의 H_목표는 절대값으로
1e-13 미만(E=300 kJ/mol에서는 1.3e-24)이고 전체의 1e-10에도 못 미친다.
따라서 `e_H = (H목표−H실제)/H목표` 는 **소성 앞 80% 구간에서 0으로 나눈다.** 그래서 외측 루프의 출력을 상대오차가 아니라

```
Δt_eq = (H_목표 − H_실제) / exp(−E/(R·T_peak))      [초]
```

로 낸다. 분모가 소성 시점과 무관한 상수라 전 구간에서 정의된다. 부수 효과가
하나 더 있다 — 이득을 곱한 보정량을 내지 않으므로 **부록 C에서 미정인 외측
루프 이득 `Kh` 가 아예 필요 없다.**

### 적재 — `loading.py` (9-2절)

점유율 = 투영 면적 합 / 선반 면적. 그 다음의 `F(점유율)`·`h(점유율)` 는
**구현하지 않는다** — α·β가 부록 C 미정이고 동정 방법이 "시뮬레이터 민감도
스윕"이라, 함수형만 코드에 박으면 조용한 기본값이 된다.

총량 이상 감지는 기대응답 대비 상대 편차 하나로 한다.

```
기대응답 = baseline_w · (1 + declared_kg · RESPONSE_PER_KG)
RESPONSE_PER_KG = 0.01586 /kg     ← 9-2절 예제(0kg 1400W · 3kg 1467W · 10kg 1622W) 역산
```

**임계값이 계통 불확실(≈10%)보다 작으면 `ValueError` 를 던진다.** 공급전압
±5%만으로 전력이 ±10% 움직이므로, 임계를 낮춰 민감하게 만들면 전압 변동을
적재 이상으로 오보한다. 9-2절이 요구한 것은 민감도가 아니라 **기능 목표를
낮추는 것**이다. 그래서 9-2절 예제의 "10kg 등록 vs 12kg 실제"(신호 차 2.7%)는
이 코드에서 **걸리지 않는다** — 그것이 정직한 결과다.

### 냉각 — `cooling.py` (9-6절)

**자연냉각률이 상한이다.** 전기가마는 열을 넣을 수만 있으므로 자연냉각보다
빠르게 식힐 방법이 없다. 상한은 구간 평균 자연냉각률로 잡는다:

```
자연냉각 소요시간 = ∫dT/rate(T)          (자연냉각률이 온도에 따라 변하므로 적분)
상한 = 구간 폭 / 자연냉각 소요시간
```

9-6절 예제(30L, C=58 kJ/K, UA는 1220℃ 유지전력 2.5kW에서 역산)를 그대로
재현한다 — 자연냉각률 1220℃ 155 / 1000℃ 127 / 800℃ 101 / 600℃ 75 [℃/h],
1100→900℃ 자연냉각 1.6h(평균 126℃/h).

서냉 비용은 08절 되돌림 비용과 같은 원칙으로 항상 병기한다:

```
P_평균 = UA·(T_평균 − T_주위) − C·(냉각률)/3600
80℃/h → 2.5h · 751W · +1.9 kWh    50 → 4.0h · 1234W · +4.9    30 → 6.7h · 1556W · +10.4
```

거부 조건 다섯: 냉각 방향이 아님 / 냉각률 ≤ 0 / 자연냉각률 초과 /
**573℃를 세그먼트 내부에서 가로지름** / 가마 최대 출력 초과. 빈 세그먼트
목록도 거부한다 — 냉각 미지정 회차가 조용히 승인되지 않게 한다.

**이 모듈은 `heatwork` 를 import하지 않는다.** 냉각을 H로 환산하지 않는다는
9-4절 결정을 구조로 못 박은 것이고, 테스트가 그것을 확인한다.

### 시뮬레이터 — `simulator.py` (12-2절)

부록 E: *"생성기와 추정 모델이 같으면 어떤 수렴도 자명하다."* 그래서 생성기를
**일부러 오지정**한다.

| | 추정 모델 (`KilnProfile`·`SegmentedController`) | 생성기 |
|---|---|---|
| 노드 | 1개 | 3개 (벽 · 기물 · 센서) |
| 손실 | 선형 `UA·(T−T_amb)` | 선형 + 복사 `σ_eff·(T⁴−T_amb⁴)` |
| 기물 | 모형화하지 않음 | 벽과 유한 열저항으로 결합 |
| 센서 | 벽 온도 = 센서 온도 | 2단 1차 지연 + 잡음 |
| 출력 | 지령 = 실제 | 전압²·열선 노후로 변형 |

기준 온도 1200℃에서만 총손실을 선형 모델과 맞춰 두어 비교가 도달 가능한
범위에서 이루어지게 하고, 그 밖의 온도에서는 어긋나게 둔다. `run()` 이
제어기에 넘기는 것은 **잡음이 얹힌 센서값뿐**이다 — 기물 온도를 넘기면
9-3절이 지적한 관측 문제 회피가 된다.

### 구간별 제어 — `controller.py` (9-4 · 9-5 · 9-2절)

| 구간 | 내측 루프 | 외측 루프 | 추종 대상 |
|---|---|---|---|
| 승온 | 온도 PID | **감시 모드** | 원본 스케줄 |
| 유지 | 온도 PID | **능동 모드** | 누적 열일 H_s |
| 냉각 | 온도 PID | **없음(단일 루프)** | 목표 냉각률 궤적 |

내측 루프는 전향보상 + 비례다: `P = UA·(T_sp−T_amb) + C·(스케줄 기울기) +
(C/τ)·(T_sp−T_s)`. 비례이득을 `C/τ` 로 **물리에서 뽑기** 때문에 가마 프로필이
바뀌어도 같은 정정 시상수를 유지한다 — 임의의 숫자를 이득으로 박지 않는다.

외측 루프는 누적 H가 목표의 **1%** 에 닿을 때 감시 → 능동으로 넘어간다.
목표 H는 지정하지 않으면 **원본 스케줄의 승온·유지 구간에서만** 계산하고,
**냉각 구간의 열이력은 적산조차 하지 않는다**(9-4절). 유지 연장은 유지
구간의 **끝**에서만 스케줄 진행을 얼어붙게 해 적용한다 — 유지 도중에 얼면
원본 스케줄의 남은 유지분이 연장분 위에 덧붙어 목표를 넘긴다.

**센서 이상(정체·급변·절대영도 이하)이면 출력 0 · 일시 정지**다. 해제
경로는 `resume()` 하나뿐이고 코드는 그것을 스스로 부르지 않는다(9-2절).
정체 판정은 **900초 창 전체의 변화량**으로 잰다 — 주기당 변화량으로 재면
100℃/h 승온이 20초 주기에서 0.55℃뿐이라 정상 승온을 정체로 오인한다.

## ③ 출력

- `heat_work(curve, E) -> float`, `heat_work_curve(...)` (누적 곡선),
  `equivalent_hold_seconds(h_deficit, peak_c, E) -> float`,
  `assume_E(값, 사유) -> AssumedE(value, note)`.
- `LoadingCheck(packing_ratio, gross_error, threshold, message)` —
  message에 계통 불확실 대비 신호 크기와 **"적재 오등록 판별이 아니다"** 가
  항상 실린다.
- `CoolingPlan(segments, feasible, rejections, extra_hours, extra_kwh,
  provenance_notes)` — 거부 사유와 서냉 비용, 선형 근사 한계 문구.
- `SimStep(t, sensor_c, ware_c, power_w)` — `power_w` 는 지령이 아니라
  **실제 투입 전력**. `KilnSimulator.provenance_notes` 가 오지정과 절대
  정확도 미담보를 나른다.
- `ControlDecision(power_w, phase, outer_mode, hold_extension_s, message,
  paused)` — `hold_extension_s` 는 9-5절 Δt_eq[초]이고 화면에는
  "유지 7분 부족"으로 뜬다. 9-7절 아키텍처 A에서는 사람이 이 값을 읽어
  기존 컨트롤러의 유지 시간에 반영한다.

**E가 가정값이라는 사실이 매 `ControlDecision.message` 에 실려 나간다.**
`constants.get("E").assume()` 을 거치므로 조용한 기본값이 될 수 없다.

## ④ 차이

부록 D의 선행 대비 위치를 이 모듈은 **두 갈래로 나눠 놓았다**. "열일 기반
제어"는 상용 컨트롤러에 유사 보정이 있어 **약하고**, "냉각률 추종(결정 성장
구간)"은 열일 제어와 분리하면 **독립 가치**가 있다. 그래서 냉각을 H에서
떼어낸 것은 물리적 정당성(급냉/서냉을 H가 구분 못 함)이자 동시에 청구항
분리 가능성이다.

단독으로 선행 대비 다른 지점 넷:

1. **모드 전환의 문턱이 상대오차가 아니라 절대 비율(목표의 1%)이고, 능동
   모드의 출력이 초 단위 등가 유지시간이다.** 상용 컨트롤러의 열일 보정은
   상대오차 기반 이득 제어인데, 그 분모는 소성 앞 구간에서 0에 붙는다.
   이 구조는 그 나눗셈 자체를 제거하고, 부수적으로 미정 이득 `Kh` 를
   요구하지 않는다.
2. **냉각을 H에서 분리해 온도–시간 곡선 그대로 다루고, 자연냉각률을 물리적
   상한으로 강제한다.** 요청 냉각률이 상한을 넘으면 거부하고 사유를 낸다.
   573℃ 석영 전이는 목적이 달라 별도 세그먼트를 요구한다. 서냉을 고르면
   추가 시간과 전력량이 함께 나온다.
3. **적재 판정이 자기 분해능의 한계를 출력에 싣는다.** 임계를 계통 불확실
   아래로 내리는 것을 코드가 거부하고, 판정 문구가 "총량 이상 감지이지
   적재 오등록 판별이 아니다"를 항상 말한다. 정확도를 과장하지 않는 것이
   구성요소다.
4. **검증 생성기가 추정 모델과 구조적으로 다르고 외란이 seed로 재현된다.**
   결과를 "수렴"이 아니라 "이 오지정과 이 외란 아래서 누적 H_s가 목표의
   1.0~1.1배"로 적을 수 있다.

## 결합 효과

이 모듈은 03절 두 루프의 **연결 지점**이다.

안쪽으로는 `kiln.thickness` 가 낸 두께와 `kiln.risk` 가 낸 위험 판정이
소성 스케줄의 선택(유지 연장·냉각률)을 바꾸고, 그 소성이 통제되어야 결과
3축(`FiringResult`)이 조성의 신호가 된다. 9-1절 ②가 말한 것이 이것이다 —
**소성이 통제되지 않으면 바깥 루프의 신호가 잡음이 된다.** 두께가 회차마다
±0.3mm 흔들리면 조성 ±2%p 차이가 그 안에 묻히듯, 소성이 회차마다 흔들리면
두께를 아무리 잘 재도 결과가 조성을 말해주지 않는다.

바깥으로는 `kiln.exchange` 가 이 모듈의 산출을 처방으로 발행한다 —
`heat_work_target`(승온·유지)과 `cooling`(온도 곡선 그대로)이 분리된 채
나가는 것이 10-3절의 요구이고, 그 분리는 여기서 이미 자료형으로 되어 있다.
변환이 **비대칭**인 이유(대상 가마의 자연냉각률이 원본보다 느리면 재현 불가)도
`cooling.py` 의 상한 판정이 그대로 근거가 된다.

그리고 이 모듈이 남기는 것은 값만이 아니다. E가 가정이라는 사실, 시뮬레이터가
