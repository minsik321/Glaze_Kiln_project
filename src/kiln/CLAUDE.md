# kiln — 패키지 공통 규율과 `constants.py`

기획서 [00절](../../docs/kiln-plan-v7.md) · [부록 C](../../docs/kiln-plan-v7.md) · [부록 D](../../docs/kiln-plan-v7.md)

모듈별 상세는 각 하위 디렉터리의 `CLAUDE.md` 에 있다. 여기는 **패키지 전체에
걸리는 규율**과 그것을 강제하는 `constants.py` 를 다룬다.

---

## 왜 계수를 값으로 다루지 않는가

기획서 00절이 주장하지 않기로 한 것 중 하나가 이것이다:

> 계수(k₁, k₂, ρ_dry, E, α, β)의 값을 주장하지 않는다. **동정 절차만 주장한다.**

그리고 부록 C는 그 이유를 특허 쪽에서 다시 말한다:

> 이 표가 명세서 실시가능성의 근거다. **값이 없어도 동정 절차가 개시되어
> 있으면 요건을 충족한다.**

계수를 그냥 `K1 = 0.55` 로 두면 이 약속이 코드 안에서 소리 없이 깨진다.
`0.55` 를 읽은 다음 사람은 그것이 문헌 추정값인지 실측값인지 알 방법이 없고,
결과 보고서에도 그 구분이 실리지 않는다. 그래서 `constants.py` 가 보관하는
것은 값이 아니라 **값과 출처와 동정 절차의 묶음**이다.

---

## ① 입력

부록 C 표 15행. 기호·정의·차원·초기값 출처·동정 방법.

## ② 처리

```python
Coefficient(symbol, definition, dimension, identification, provenance,
            _value, lower, upper, note)
```

`Provenance` 가 다섯 단계다:

| 값 | 뜻 | `.is_trustworthy` |
|---|---|---|
| `UNDETERMINED` | 값 기재 금지. 동정 절차만 존재 | ✗ |
| `LITERATURE` | 문헌 추정 초기값. 캘리브레이션 전 | ✗ |
| `CONVENTION` | 문헌 관행. 실측 근거 없음 | ✗ |
| `CALIBRATED` | 이 사용자·이 유약의 실측에서 동정됨 | ✓ |
| `USER` | 사용자가 직접 넣음 | ✓ |

**핵심 동작 세 가지:**

1. **`UNDETERMINED` 계수의 `.value` 는 던진다.** `UndeterminedCoefficientError`
   가 동정 절차를 메시지에 실어 준다. 대상: `E alpha beta Kh sensor_offset`.
2. **`.assume(값, 사유)` 는 provenance를 올리지 않는다.** 민감도 스윕은 가능해야
   하지만 결과에서 "가정에 근거함"이 지워지면 안 된다.
3. **`.calibrated(값, 출처)` 만이 `CALIBRATED` 로 올린다.** 실측이 있었다는 뜻이다.

## ③ 출력

`REGISTRY: dict[str, Coefficient]`, `get(symbol)`,
`Coefficient.annotation()` — 화면·보고서 병기 문구
(`"(문헌 추정 초기값 · 캘리브레이션 전)"` 등, 6-4 · 8-4절).

## ④ 차이

상용 도구는 계수를 상수로 박거나 사용자에게 숫자 입력을 요구한다. 어느 쪽도
**그 숫자가 어디서 왔는지**를 결과와 함께 나르지 않는다. 이 모듈은 계수를
provenance와 묶어 두고, 미정값은 **읽기 자체를 실패시켜** 조용한 기본값이
생기는 경로를 막는다. 부록 C가 명세서 실시가능성의 근거이므로, 그 대장이
문서에만 있고 코드에는 없으면 실시가능성 주장과 구현이 어긋난다.

## 패키지 전체에 걸리는 규율

**의존은 한 방향이며 순환하지 않는다.**

```
constants ─┐
domain ────┼─→ chem ────→ search
           ├─→ batch ───→ thickness ─→ risk
           │                  └───────→ calibration
           └─→ firing ──→ exchange

webapp ─── 위 전부에 의존한다 (UI 경계. 계산하지 않고 직렬화만 한다)
```

`domain` 은 `constants` 외에 아무 데도 의존하지 않고 계산 로직을 두지 않는다.
경계 자료형과 시그니처는 [docs/INTERFACES.md](../../docs/INTERFACES.md)에서
고정되어 있다.

**순수 stdlib.** 서드파티 의존은 pytest뿐이다. 부록 D의 기재 포맷
(① 입력 ② 처리 ③ 출력 ④ 차이)에 수식을 그대로 옮기려면 수식이 라이브러리
호출 뒤에 숨어 있으면 안 된다.

**모듈마다 `CLAUDE.md` 를 부록 D 4항목 형식으로 쓴다.** 부록 D의 논거가 그대로
적용된다 — 구성요소를 많이 묶은 청구항은 넓어지지 않고 좁아지고, 모듈마다
선행 대비 위치가 다르다. 문서를 모듈별로 독립 기재해 두면 변리사가 쪼갤 수도
있고 묶을 수도 있다. **통합만 서술하면 쪼갤 재료가 없다.**

**폐기된 설계를 되살리지 말 것.** [docs/DECISIONS.md](../../docs/DECISIONS.md)에
v5에서 한 번씩 틀렸던 설계들이 이유와 함께 정리되어 있다. 리팩터링 중
"단순화"처럼 보이는 것들이 대부분 거기 있다.
