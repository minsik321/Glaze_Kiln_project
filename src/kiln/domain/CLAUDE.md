# kiln.domain — 데이터 모델과 좌표계

기획서 [11절](../../../docs/kiln-plan-v7.md) · [4-1절](../../../docs/kiln-plan-v7.md) · [10-1절](../../../docs/kiln-plan-v7.md)

의존 방향의 바닥이다. `kiln.constants` 외에는 아무 데도 의존하지 않으며,
**계산 로직을 두지 않는다.** 좌표계의 거리처럼 자료형 자체에 딸린 연산만 둔다.

---

## ① 입력

| 출처 | 무엇 |
|---|---|
| 사용자 | 레시피 원료 비율, 기물 형태·소지·초벌 온도, 목표 좌표, 결과 3축 라벨 |
| 저울 | 시유 전 / 건조 후 무게 |
| 비중계 | 실측 비중 + 측정 시각 + 교반 후 경과 |
| 가마 | 설정 스케줄, 센서 실측 곡선 |

## ② 처리

자료형이 **불변식을 강제**하는 것이 이 모듈의 처리 전부다. 검증을 호출부에
맡기면 같은 검사가 여러 곳에 흩어지고 결국 어딘가는 빠진다.

| 불변식 | 근거 |
|---|---|
| `GlazeRecipe`: 원료 비율 합 = 100% (±0.5) | 배합의 정의 |
| `DensityMeasurement`: 비중 > 1.0 | 물보다 가벼운 슬립은 없다 |
| `WareShape`: z가 단조증가, r ≥ 0 | 회전체 프로파일의 적분 가능 조건 (7-1) |
| `GlazingRecord`: 건조 후 ≥ 시유 전 | 총량 앵커 W ≥ 0 (7-2) |
| `GlazingRecord`: 담금이면 `dip_seconds` 필수 | 6-1절 역산의 입력 |
| `FiringResult`: 등급=실패 ⟺ 실패 유형 존재 | 10-2절 안전 범위 보정의 신호 |
| `FiringResult`: 파단면 위치만 있고 두께가 없으면 거부 | 위치는 부가 정보이지 관측이 아니다 (7-7) |

### 순서형 축 (`OrdinalAxis`)

광택도와 투명도는 **독립 2축**이고 둘 다 **순서형**이다. 순서형이라는 것이
두 가지를 준다 — 거리가 정의되고(5-4절 목적함수), 사용자가 소성 결과를 목표와
같은 척도로 고를 수 있다(⑬ 되먹임).

```
광택도  Dry(0) — Matte(1) — Satin(2) — Semi-gloss(3) — Gloss(4)
투명도  불투명(0) — 반불투명(1) — 반투명(2) — 투명(3)
```

`distance()` 는 **다른 축 사이에서 `TypeError` 를 던진다.** 두 축이 독립이라는
사실이 주석이 아니라 자료형에 박혀 있어야 한다.

## ③ 출력

`TargetCoordinate GlazeRecipe Batch DensityMeasurement WareShape Ware
GlazingRecord CoolingSegment FiringResult FiringRun KilnProfile
CoefficientTable SearchState` 와 열거형
`Gloss Transparency Grade FailureType GlazingMethod RiskType RiskLevel`.

`KilnProfile.natural_cooling_rate(T)` 만이 예외적으로 계산을 한다 — 곡선이
등록되어 있으면 선형 보간, 없으면 `UA·(T−T_amb)/C` 로 물리 역산한다.
이 값이 [9-6절](../../../docs/kiln-plan-v7.md)의 **제어 상한**이다.

## ④ 차이 — 이 모듈이 단독으로 다른 점

**다섯 가지가 스키마 수준의 주장이다.**

**1. 비중이 배치가 아니라 순간에 귀속된다.** `Batch` 에는 비중 필드가 없고
`DensityMeasurement` 가 별도 엔티티다. 비중을 재고 몇 분 뒤 담그면 이미 다르고,
점토가 적은 배합일수록 침강이 빠르다 (6-3절). 배치에 비중을 달아두면 그
시간차가 기록에서 소실된다 — 01절이 말하는 "정보의 소실"이 스키마에서
재생산되는 경로다.

**2. 등급과 목표 좌표가 다른 축이다.** 3단계 등급(의도일치/허용/실패)은
만족도이지 질감이 아니다. 그것만으로는 탐색도 Stull 경계 보정도 못 한다.
그래서 `FiringResult` 는 좌표와 등급을 **둘 다** 들고 있고, 어느 쪽도 다른
쪽에서 유도되지 않는다 (10-1절).

**3. 가마 프로필이 복수다.** 등록 실물은 1대지만 처방 변환 검증(12-2절)에
프로필 2종이 필요하다. "가마 1대"는 사용자 소유 대수이지 스키마 제약이 아니다.

**4. 냉각이 설정 스케줄과 분리되어 회차에 붙어 있다.** `FiringRun` 은
`schedule`(온도–시간 점열)과 `cooling`(`CoolingSegment` 열)을 **따로** 들고
있다. H는 급냉과 서냉을 구분하지 못하므로(9-4절: 둘 다 H=7801) 냉각은
접히지 않는 축으로 남아야 하고, 그 사실이 스키마에 있어야 10-3절 처방이
"H_s + 냉각 곡선"으로 발행된다. 그래서 `CoolingSegment` 는 판정 로직이 있는
`kiln.firing.cooling` 이 아니라 **도메인에** 산다(거기서 그대로 재수출된다).

**5. 계수 표가 출처와 동정 조건을 들고 다닌다.** `CoefficientTable` 의
`provenance_notes` 와 `calibrated_bisque_c` 가 그것이다. 값만 나르면
"가정한 ρ_dry 위에서 낸 k₁"과 "캘리퍼로 닫은 k₁"이 되먹임 경로에서
구분되지 않고, 초벌 온도가 바뀐 것을 알아채지 못해 7-5절 **재캘리브레이션
트리거**가 흡수율로 조용히 흡수된다 — 흡수율은 k₁과 곱으로만 식별되므로
(부록 A) 그러면 k₁이 다른 물리량을 가리키기 시작한다.

### 폐기된 설계

**Dry–Matte–Clear 삼각좌표.** 셋은 배타적 성분이 아니라 용융도가 올라가는 한
축 위의 순서이고, 표면은 한 상태만 가지므로 "Dry 60 / Matte 30 / Clear 10"이
정의되지 않는다. 더 결정적으로 **소성 결과를 그 척도로 매기는 방법이 없다.**
목표와 결과가 같은 척도 위에 있어야 되먹임이 성립한다 (4-1절).

### 주의 — `RiskLevel.UNAVAILABLE`

`UNAVAILABLE.level == -1` 로 `NONE(0)` 보다 **아래**다. 담금이 아니어서 분포
기반 판정이 불가능할 때 위험을 '없음'으로 내리면 거짓 안심이 된다 (8-2절).
정렬·비교 시 이 부호를 깨지 말 것.
